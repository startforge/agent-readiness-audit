I What it actually answers

  1. Do tool calls go through a permission gate, or can they bypass it?
  2. Is model output schema-validated before anything runs?
  3. Is there a step, time, or cost budget — or can a loop run forever?
  4. Do delete, pay, publish, or messaging actions require confirmation?
  5. Are logs and traces redacting secrets?
  6. Are there repeatable tests, or only a demo?

II How a review works

One command. The scanner never pretends a keyword is a gate. Frameworks are recognized from package.json; internals in node_modules are not treated as proof.

  1. Manifests first

    Read package.json / Python lockfiles. If Mastra, LangGraph, or LangChain is declared, search project source for constructors and init parameters such as maxSteps, createTool, recursion_limit, interrupt_before.

  2. Then the rest of the chain

    Those parameters cover loop, schema, and budget shortcuts only. Permissions, confirmation, redaction, evals, and your own tool execute paths are still read in the project.

  3. Custom runtimes

    No framework? Walk runtime, tools, security, workflow, and tests the same way. Structural analysis checks that a helper is actually called from the executor — unused authorize() cannot pass.

  4. A bundle you can keep

    Writes agent-review/ in the target: HTML report, Excel workbook, JSON/Markdown data, file map, and a receipt so the next review does not re-read unchanged files.
